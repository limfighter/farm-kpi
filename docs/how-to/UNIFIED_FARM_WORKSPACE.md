# 하나의 Farm KPI 농장 경영 워크스페이스

**목표:** 분산된 작목별 손익, 농장 전체 자원, 등급별 출하, 일별 설비, 대출 및 스트레스를 하나의 JSON과 하나의 결과 HTML/JSON으로 실행합니다. 실제 농사·대출·시설 투자를 승인한 것은 아닙니다.

## 단일 실행

Python 개발 환경에서 다음 한 명령으로 계산합니다.

    python scripts/run_farm_workspace.py --input data/templates/farm_workspace_SYNTHETIC.json --log data/templates/field_log_SYNTHETIC.csv --output output/farm-workspace.json --html output/farm-workspace.html

생성된 HTML에는 작물×시설×구획, 월별 하나의 농장 현금원장, 노동/관수/전력, 등급별 판매, 일별 펌프·전력, 대출, 스트레스, 별도 영농기록 집계가 모두 표시됩니다. 모든 샘플 금액은 A 가정입니다. 실제로 가상 입력을 바꾸고 재실행하려면 JSON 파일을 수정해야 합니다. 오프라인 HTML은 자체 계산 가능한 웹앱이 아니라 Python의 계산 결과입니다.

## 입력 형식

최상위 필드 여섯 개: schema_version=1, disclaimer, portfolio, grade_lots_by_case, physical_detail, stress.

- portfolio: 기존 정식 농장 통합 입력. 유일한 월별 회계 원장의 기준입니다.
- grade_lots_by_case: 작형 case_id별 등급 lot 배열. 기존 판매를 대체하고 포장비는 출하월에 한 번만 기록. 사용하지 않을 때는 빈 객체입니다.
- physical_detail: 일별 작기·용수·전력·대출 입력 또는 null. 가정형 대출 상환표를 만들 경우 portfolio.financing_events는 반드시 빈 배열이어야 합니다.
- stress: 가격·수확량 및 용수/전력 공급 충격 시나리오 또는 null. 변경한 통합 원장을 대상으로 차액을 계산합니다.
- --log: 파일 경로는 JSON에 넣지 않고 명령행에서만 선택. 로컬의 비식별 실제 영농일지를 별도 집계하며 원장 현금에 다시 더하지 않습니다.

**중요한 계산 제한:** 등급별 포장비가 물량에 따라 발생하면서 같은 작물의 수확량까지 스트레스로 바꾸면 현 스트레스 계산기는 포장비가 바뀌는 규모를 추정하지 못합니다. 계산을 거절하며 고정비로 잘못 대체하지 않습니다.

## 계산 순서와 회계 제약

1. 원본 농장 장부의 작물·월별 노동·시설·대출·작기를 검증합니다.
2. 등급 입력이 있다면 상품화 수량의 합계를 대조하고 원래 판매를 완전히 교체합니다. 운송비 중복 계상을 막고 포장비를 하나의 공동 현금장부에 기록합니다.
3. 일별 용수·전기 및 생육단계 일정을 같은 계획과 대조하고, 선택한 원리금 현금 일정을 연결합니다.
4. 농장 전체 portfolio 계산 결과를 authoritative_portfolio로 고정하고 스트레스 기준 현금과 일별 금융현금을 다시 대조합니다. 결과가 다르면 오류 처리합니다.
5. 실제 O/T 자료는 비공개 CSV 부분집계로만 보여주며 가정 매출에 자동으로 더하지 않습니다.

## 남아 있는 개별 레거시 화면

51작목을 검색하거나 사용자 지정 작물을 입력하는 dashboard/universe/index.html은 계속 사용할 수 있습니다. 하지만 **그 화면의 JSON과 이 통합 JSON의 자동 변환 및 양방향 동기화는 아직 미구현**입니다. 기존 CLI를 제거하지 않은 것은 하위 호환성 때문이며, 신규 다년 농장 계획의 분석 실행에는 위 한 명령을 권장합니다.

실제 경작 가능 면적, 토양·배수·법률, 물/전력 유량·인입, 구매처·등급·정산, 시설 실견적·대출 심사가 확보되지 않아 특정 작물이나 시설 우위를 추천하지 않습니다. 상세 현장 제약은 [P0/P1 감사](../reference/FARM_READINESS_GAP_AUDIT.md)에서 확인합니다.
