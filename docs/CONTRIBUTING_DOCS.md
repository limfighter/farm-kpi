# 문서 운영 규칙

**목적:** 규모가 작은 Farm KPI에서도 누구든 문서를 찾고, 출처를 검증하고, 새 세션에서 맥락을 재구성할 수 있도록 합니다. GitLab handbook-first와 Diátaxis를 **경량화**해 씁니다. [채택 이유와 원전](explanation/DOCS_DESIGN_SOURCES.md).

## 저장할 위치 선택

| 질문 | 장소 |
| --- | --- |
| 현재 의사결정/자료 충족도는? | [STATUS.md](STATUS.md)만 수정 |
| 실행 순서/명령이 필요한가? | 기존 how-to 문서 또는 [how-to/](how-to/GET_STARTED.md) |
| 필드명·파일·통화·단위는 무엇인가? | [reference/](reference/DATA_CONTRACTS.md) |
| 가정이 왜 위험한가? | [explanation/](explanation/MODEL_BOUNDARIES.md) |
| 앞으로 무엇을 왜 채택/거부하기로 했나? | [decisions/](decisions/README.md)에 ADR |
| 단발성 세션 정리는? | 날짜가 붙은 인수인계 기록. **현재 상태 표 대신 쓰지 않음** |
| 전체 목록 및 책임은? | [catalog.json](catalog.json)을 갱신하고 [문서 허브](README.md)에 필요한 진입점을 추가 |

**기존 파일을 이동하지 않는 이유:** 이미 여러 HTML, README, 문서가 상대경로로 연결되어 있습니다. 경로 변경 이득이 명확하지 않으면 링크 안정성과 변경 범위 최소화를 우선합니다.

## 문서 작성 규칙

1. 첫 화면에 **목적, 대상 독자, 현재 사용 가능/미완료 상태**를 둡니다.
2. 사실은 **출처 → 관측연도 → 지역 → 10a/작기 및 통화 단위 → 검증 상태(R/O/Q/T/A)**가 따라오게 합니다. 인증하지 않은 것은 검증이라 쓰지 않습니다.
3. 목표 달성 절차에는 **입력, 실행, 예상 결과, 실패 시 확인할 것**을 작성합니다. 실행해 보지 않은 명령은 추측으로 넣지 않습니다.
4. 결정 ADR에는 **검토한 대안, 근거, 위험, 날짜, 상태, 결과**가 모두 필요합니다. 날짜가 붙은 ADR의 과거 상태를 소급 수정하지 않고 변경 시 새 ADR을 작성합니다.
5. 숫자를 중복 복사하지 말고 원본 CSV·설정·[데이터 계약](reference/DATA_CONTRACTS.md)에 링크합니다.
6. 문서에 정확한 농지 주소, 계좌, 실거래 원본, 기밀 견적, 키를 포함하지 않습니다. 로컬 민감 자료는 \`data/private/\`, 결과는 \`output/\`으로 제한합니다.
7. 내용과 코드가 바뀌는 **같은 PR**에서 문서를 수정합니다. 날짜가 붙은 세션 기록만 갱신하고 [STATUS.md](STATUS.md)를 놓치지 마세요.

## PR 체크리스트

- [ ] 문서 허브에서 해당 절차에 도달할 수 있다.
- [ ] [catalog.json](catalog.json)에 모든 새/변경 문서의 분류와 유지관리 역할이 기록된다.
- [ ] 경로와 상대링크가 맞고 \`python scripts/check_docs.py --check\` 통과.
- [ ] \`pytest -q\`와 기존 데이터/대시보드 동기화 테스트 통과.
- [ ] 실제/보고/가정 및 누락자료를 구별하고, \`STATUS.md\` 내용과 모순되지 않는다.
- [ ] 공개 링크를 인용할 때 원문 페이지를 적는다. 링크가 살아있는지 별도로 검토한다(오프라인 CI는 외부 페이지 상태를 검사하지 않는다).
- [ ] 코드/모델 결과를 바꾸는 문서 PR이 아니라면 기상·수익 수치를 수정하지 않는다.

## 유지관리 역할

- **상태/로드맵:** 프로젝트 의사결정자(최종 내용 확인) + 저장소 유지관리자(버전 관리).
- **보고/관측 자료 설명:** 데이터 조사 담당(숫자·출처·연도 검토) + 구현 담당(검증 스크립트).
- **재무·위험 모델:** 모델 담당(실행 근거) + 실제 투자 결정자는 별도 승인.
- **새 결정:** 작성자 제안 → 증거 검토 → PR 리뷰 → 기록. 코드 병합은 작물 선정이나 투자 승인과 무관합니다.

## 테스트와 제한

\`\`\`bash
python scripts/check_docs.py --check
python -m pytest -q
\`\`\`

문서 검사기는 **저장소 내부 Markdown 상대링크, 카탈로그 완전성, ADR 필드 형식**만 확인합니다. 외부 URL의 실제 접근성이나 출처의 진위, 재배 가능성은 검사하지 못합니다. 신규 서류 검증은 [농지·RDA 조사](RDA_AUDIT_AND_SITE_INTAKE.md) 절차를 따릅니다.
