# 세션 10 — 오프라인 탐색·준비도·모형 연결

**목표:** 작목 탐색에서 현장 근거와 비교 가능한 모형 결과까지 사용자가 출처와 결측을 따라갈 수 있게 연결합니다. **책임:** 개발 담당과 운영자 사용성 검토. **로드맵:** P2-03. 상태 기준은 [STATUS](../STATUS.md)입니다.

## 입력·선행조건

- 기존 `dashboard/`의 탐색기·준비도·현장 입력·출처 커버리지·예시 트리맵과 [08](08-evidence-gated-model.md)·[09](09-robust-comparison.md)의 계약.
- 후보 근거가 미완료여도 탐색·누락 표시와 화면 연결은 구현할 수 있습니다. 검증된 결과 없이 정량 후보 순위를 보여주지는 않습니다.
- 비공개 입력은 브라우저 로컬에서 읽고 저장하며 기존 파일의 링크 경로와 오프라인 실행을 유지합니다.

## 실행 순서

1. 작목→재배방식/작기→필수 근거→결과 화면의 연결과 표시 규칙을 설계합니다. 기존 브라운·세이지 구성과 접근성, 작은 화면을 고려합니다.
2. R/O/T/Q/A, 연도·지역·단위·작기·PDF/웹 검토 상태를 결과와 함께 표시합니다. 조사 소득과 사업 현금흐름은 각 의미가 보이는 별도 항목으로 연결합니다.
3. 후보 pending 이유, 실제로 막힌 근거와 다음 확인 항목을 표시합니다. 클릭/사용자 자기신고만으로 VERIFIED 상태로 승격하지 않습니다.
4. 로컬 JSON 가져오기·결과 내보내기에서 형식 오류·버전 오류·민감정보 포함 입력을 검사합니다. 사용자 입력 문자열의 HTML 실행과 외부 전송을 차단합니다.
5. 개인 자료를 제외한 기본 화면을 재생성하고 화면·CSV·패키지 결과의 일치를 확인합니다. 사적 JSON과 렌더링 결과는 저장소에 추가하지 않습니다.

## 산출물·완료 기준

- 기존 화면의 연결·출처 표시·로컬 입력 기능, 필요한 생성 스크립트와 UI/개인정보 회귀 검사, 사용법 문서.
- 네트워크 없이 주요 기능이 동작하고, 숫자 0과 UNKNOWN이 구별되며, 출처에서 결과까지 추적할 수 있어야 합니다.
- 브라우저에서 파일 가져오기/잘못된 JSON/후보 없음/키보드 조작/작은 화면과 외부 요청 부재를 확인합니다. 자동 검사와 수동 확인 범위를 각각 기록합니다.

## 기존 회귀 검사

```bash
python -m pytest -q tests/test_dashboard.py tests/test_crop_discovery.py tests/test_crop_feasibility.py tests/test_site_intake_ui.py tests/test_rda_web_board.py
python -m pytest -q
python scripts/check_docs.py --check
```

새 UI 동작의 검사를 추가하고 변경된 모든 생성 파일에 해당 `--check`를 실행합니다. [공통 종료 규칙](README.md)에 따라 정확한 HEAD의 CI도 확인합니다.

## 재개 프롬프트

> AGENTS.md, docs/STATUS.md, docs/sessions/10-offline-integration.md를 읽고 기존 오프라인 화면부터 확인해. 출처·누락·후보 모형을 연결하는 작은 흐름 한 가지를 설계·구현·검증해. 개인정보 전송과 사용자 클릭에 의한 검증 승격을 막고 실제 결과가 없는 후보는 pending으로 표시해.
