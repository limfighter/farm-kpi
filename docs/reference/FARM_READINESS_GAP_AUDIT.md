## 이번 수정의 검증 범위와 한계

- 중복 내역 방지, 미측정/null과 실제 0 구별, 보고서 불필요 날짜 제거, 물/전력 월별 공급 미충족 상태가 재무 결과와 함께 보이도록 개선했습니다.
- CSV 출처 T/O는 사용자의 자체 표기이며 독립적으로 실거래증빙을 대조하지 않습니다. 기존 가상 영농일지/스트레스는 전부 A입니다.
- 복수 거래가 동일 구매자에게서 들어올 때는 **각 별도의 입금 사건에 서로 다른 비식별 ID**를 붙여야 합니다. 분할 입금, 선급금, 반품 환불, 미수금 잔액, 세금·보험/보조금까지 자동 대사하지 않습니다.
- **물 부족으로 수익이 0원 덜 들어온다는 분석이 아닙니다**. 물·전기 부족이 있어도 판매량을 자동 감소시키지 않는 경제 모형의 제약입니다. 사용자 입력·현장 확인 전에는 수익성을 추천하지 않습니다.
- 현재 출력은 case_id와 시나리오 설명을 표시합니다. 원본 계약·영수증·계좌·연락처·필지 주소/좌표는 GitHub 또는 공유 HTML에 포함하지 마세요.

## 바로 이어질 작업 순서

1. 유효 경작 면적/토양·배수/물·전기 공급/허가/월별 노동력의 **현장 P0 가능 여부 확인**. 제공받지 못한 값은 UNKNOWN 그대로 둡니다.
2. 실제 수확·등급·가격·계약 수수료·정산 지연과 자재·고용·수리·시설 신축/임대·금융 조건을 익명·집계 가능한 범위에서 확보하고 가상 입력을 **해당 입력에 한해** 보정.
3. 반품·취소·분할정산·거래별 미수금 잔액을 대사하는 연결 ID, 데이터 기간 완전성, 브라우저/파이썬 현금 계산 동등성 시험, 일 단위 공용 재배 구획을 검증.
4. 위 조건을 충족한 대안에 한하여 현금 부족 피크·자가/고용노동·실수취가/상품등급/불리한 시나리오를 함께 비교합니다. 전국 소득 51행을 순위 점수로 복사하지 않습니다.
