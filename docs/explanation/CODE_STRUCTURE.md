# 코드 구조와 리팩터링 경계

**대상:** 개발·검증 담당. **목적:** 공통 검증 규칙의 위치와 계산 변경 시 지켜야 할 경계를 설명합니다. 실제 자료 충족도와 의사결정 상태는 [STATUS](../STATUS.md)에서 관리합니다.

## 책임과 의존성

| 위치 | 책임 | 경계 |
| --- | --- | --- |
| `src/farm_strategy/cli.py` | 인자 파싱, 명령별 호출, JSON 출력 | 모델 입력이 필요 없는 현장·증빙 검사는 별도 처리 |
| `src/farm_strategy/reported.py` | 2024 전국 51개 작목의 공통 파싱·검증 | 명시적인 경로/행을 받고 보고 통계 R만 허용; 시뮬레이션과 독립 |
| `src/farm_strategy/sampling.py` | 기상 표본 선택과 분위수 보간 | 파일 입출력·난수 생성·사업 판단 없음 |
| `src/farm_strategy/model.py` | 한 경로의 가상 재무 계산과 단일 계획 집계 | 기존 다섯 예시 계획과 가정 기반 반응식 |
| `src/farm_strategy/comparison.py` | 같은 충격을 사용하는 계획·시나리오 비교 | 경로별 공통 seed와 차이 집계, CSV 계약 유지 |
| `src/farm_strategy/lifecycle.py` | 1~10년 명시적 작업/작형/판매/시설/보증금 이벤트 계산 | 기존 다섯 시나리오와 독립, 현금 계정만; RDA 성목 소득/가상 연실적 자동 복사 금지 |
| `src/farm_strategy/workflow.py` | 작업/판매/시설 사건 기반 1년 작물×시설 비교(가정/근거 표지) | 기존 5전략 몬테카를로와 별개. 감가상각·대출·장기 ROI 미구현; 진짜 작목 적합성 인증 금지 |
| `src/farm_strategy/cashflow.py` | 월별 배분, 명목→실질 변환, 비용 정합성 | 설명되지 않은 차액은 오류; 수리비로 흡수 금지 |
| `src/farm_strategy/evidence.py`, `calibration.py`, `site_intake.py` | 비공개 증빙 형식, 검토 기반 미리보기, 현장 누락정보 | 기존 개인정보·해시·출력 경로 제한 유지 |
| `scripts/build_crop_universe.py`, `dashboard/universe/` | 51개 공표 작목 전수+사용자 입력 작목 탐색, 오프라인 시뮬레이터 폼/JSON 생성 | 보고값(R)과 모델 입력(A/T/Q 등)을 혼합하지 않음; CSV→HTML 정합성 CI 검사 |
| `scripts/` | 문서·출처 감사와 오프라인 화면 생성 | 재사용하는 51작목 검증은 패키지에 위임 |

주요 계산 의존성은 `cli → calibration → comparison → model → cashflow`입니다. `model`과 `comparison`은 `sampling`을 사용하고, 작목 탐색·준비도·장기형 이력 검사기는 `reported`를 사용합니다. 공통 모듈이 CLI나 화면 생성 스크립트를 역으로 참조하지 않습니다.

## 분석에서 확인한 문제와 조치

| 문제 | 영향 | 조치 |
| --- | --- | --- |
| 탐색기와 준비도 생성기에 서로 다른 51작목 검증 구현 | 준비도 생성기가 PDF 페이지 0 또는 NaN 소득률을 받아들임 | 같은 검증 규칙을 공유. 준비도용 행의 기존 문자열/수치 표현과 출력 바이트는 보존 |
| 단일 계획과 비교기의 기상 표본 선택·분위수 중복 | 한쪽만 수정하면 같은 입력을 다르게 해석할 위험 | 공통 보조 함수로 추출하고 기존 import 경로 유지 |
| CLI 한 함수에서 파싱·입력 로드·분기·저장 수행 | 새 명령 추가 시 불필요한 모델 파일 의존 가능 | 파서, 명령 처리, JSON 출력을 분리하고 실제 명령 회귀 검사 |
| 웹 표본의 다섯 수치 중 세 금액만 잠금 | 수량·가격 변조가 검사를 통과 | 기존 캡처의 수량·가격까지 비교. 새 원문 검증이나 PDF 검증 승격은 아님 |

보고 통계 원본, 모델 설정, 파생 CSV와 생성 HTML은 구조 개선의 편의를 위해 수정하지 않습니다. 공통 검증 강화로 기존 준비도 생성기가 허용하던 잘못된 입력은 이제 거부합니다.

## 계산 결과를 보존하는 규칙

- `one_path`의 기상 선택, 가격·병해충·시설 수리 난수 추출 순서를 유지합니다. 시설이 없어도 수리 난수 하나를 소비해야 계획 간 충격이 정렬됩니다.
- `simulate`의 연속 난수 스트림과 `compare_plans`의 경로별 64비트 seed 방식을 합치지 않습니다.
- 단일 계획의 `statistics.median`과 비교기의 보간 분위수 중앙값 계산은 각각 유지합니다. 수학적 동치가 부동소수점 결과의 동치를 보장하지 않습니다.
- 명목 `debt_end`, 실질 부채, 자기노동 기회비용, 월말 현금, 명시적 수리비의 의미를 유지합니다.
- 기존 함수 import, CLI 옵션·기본값, JSON 키, CSV 헤더와 오프라인 화면 경로를 유지합니다.

[데이터 계약](../reference/DATA_CONTRACTS.md)의 UNKNOWN·연도·지역·10a·작기·명목/실질 구분도 동일하게 적용합니다.

## 후속 개선 후보

1. **운영비 구성요소:** 연간 모형과 월별 장부의 일부 비용 공식이 중복됩니다. 향후 이름 있는 비용 구성요소를 공유하되, 월↔연간 독립 정합성 검사는 남겨야 합니다. 이번 변경은 회계 공식을 옮기지 않습니다.
2. **일반 wheel 배포:** CLI 기본 설정·기상 경로는 저장소 배치를 기준으로 찾습니다. 현재 지원 절차는 [editable 설치](../how-to/GET_STARTED.md)입니다. 저장소 밖 배포에는 데이터 리소스 정책을 먼저 정해야 하며, 명시적 `--config`·`--weather` 경로가 필요합니다.
3. **나머지 스크립트 경계:** 웹 표본 검증과 화면 생성 사이의 스크립트 import, 대시보드의 계획·시나리오 식별자 중복은 남아 있습니다. 규모가 커질 때 해당 기능 단위로 패키지에 옮길 수 있습니다.
4. **모델 범용화:** 2027/2028/2030/2036 시점과 다섯 계획은 현재 예시에 특화되어 있습니다. 다른 작목으로 일반화하려면 별도 근거·계약·작기 설계가 필요합니다.

## 검증 방법

전체 테스트와 [CI](../../.github/workflows/ci.yml)의 출처·문서·화면 재현성 명령을 함께 실행합니다. 구조 변경 시에는 변경 전 코드의 동일 seed 결과와 상세 경로·단일 계획 요약·계획 비교 결과를 직접 대조합니다. 로컬 테스트 통과와 원격 push/PR CI 통과는 별도로 보고합니다. 원본 PDF나 현장 자료가 없는 검증의 한계는 [모델 경계](MODEL_BOUNDARIES.md)와 [RDA 웹 표본](../reference/RDA_WEB_EVIDENCE_SAMPLE.md)에 따릅니다.


## 단일 최상위 분석 파이프라인

이제 scripts/run_farm_workspace.py -> farm_strategy.farm_workspace.run_farm_workspace가 모든 현금 관련 기존 코드를 한 번에 연결합니다. lifecycle은 작물별 원장, execution_detail은 등급 수량·포장비 검증, portfolio는 공통 농장 현금, physical_operations는 일별 자원/금융 사건, farm_records_stress는 하락위험/부분 영농기록을 담당합니다. 모듈별 현금을 단순히 더하지 않고 최종 authoritative_portfolio에 모든 중복 없는 현금을 반영합니다.

구형 CLI/화면은 소스 감사·하위 호환 때문에 보존됩니다. 레거시 51작목 편집기는 아직 통합 입력 포맷으로 자동 변환하지 못하므로 단일 계산 흐름 구현을 모든 편집 UI의 통일이라고 주장하지 않습니다.


**브라우저 한 곳:** scripts/serve_farm_workspace.py는 Python 표준 라이브러리의 loopback-only HTTP 서버로 단일 JSON 편집·비식별 로컬 CSV/계산·결과 표시를 제공합니다. 서버 내 계산은 동일 run_farm_workspace와 render_html을 호출합니다. 업로드 CSV는 문자열 버퍼로만 처리하며 디스크에 임시 저장하지 않습니다. 외부 배포·원격 인증/실시간 데이터·브라우저 안 모델 자체 복제는 지원하지 않습니다.
